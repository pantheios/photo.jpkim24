# 시스템 아키텍처

> **소스:** [README.md](../../README.md), [src/middleware.ts](../../src/middleware.ts), [src/instrumentation.ts](../../src/instrumentation.ts), [scripts/mac-server/start.sh](../../scripts/mac-server/start.sh)

bebememo를 대체하는 **셀프호스팅 가족 사진 공유 서비스**. 초대받은 가족만 들어오는 비공개 공간에 사진·동영상을 올리고 댓글·이모지 반응을 남긴다. 아기 생일을 등록하면 모든 사진에 "생후 N일"이 자동 표시된다.

## 기술 스택

Next.js 16 (App Router) · Prisma 7 + SQLite (better-sqlite3 어댑터) · sharp · Tailwind CSS 4 · JWT 세션(jose) · PWA.

## 런타임 구성

- **웹 서버**: Next.js. 페이지(서버 컴포넌트)와 API 라우트를 한 프로세스에서 서빙. 대부분 `runtime = "nodejs"`.
- **미들웨어**: Edge에서 세션 쿠키만 검증 → 비로그인 차단. `next/headers`·prisma 의존 없는 순수 토큰 함수([session.ts](../../src/lib/session.ts))만 사용.
- **백그라운드 타이머**: `instrumentation.register()`가 서버 시작 시 1회 실행 → Node 런타임이면 iCloud 주기 동기화 타이머 가동([instrumentation-node.ts](../../src/instrumentation-node.ts)).
- **맥 동기화 에이전트**: 별도 머신(맥)의 `launchd`가 1시간마다 [sync.py](../../scripts/mac-sync/sync.py) 실행 → 서버 `/api/ingest`로 업로드. ([사진 동기화 개요](사진_동기화_개요.md) 참고)

## 데이터 흐름

```
[가족 브라우저] ──로그인(JWT 쿠키)──▶ 미들웨어 검증 ──▶ 페이지/API
        │
        ├─ 직접 업로드:  /api/upload  → media 파이프라인 → DB+디스크
        └─ 사진 보기:    /media/*     → 인증 후 파일 서빙(Range 지원)

[맥 사진앱] ─osxphotos→ [임시폴더] ─sync.py→ /api/ingest → media 파이프라인 → DB+디스크
[iCloud 공유앨범] ─webstream API→ 주기 타이머 → media 파이프라인 → DB+디스크 (현재 비활성)
```

세 입력 경로(직접 업로드·맥 동기화·iCloud)가 모두 **공통 미디어 파이프라인**([media.ts](../../src/lib/media.ts))을 거쳐 표시용 JPEG·썸네일을 만들고, **촬영일(KST)별로 한 게시물(Post)에 묶인다**.

## 저장 구조

- **SQLite DB**(`DATABASE_URL`, 예: 외장SSD `app.db`) — 모든 메타데이터
- **업로드 디렉터리**(`UPLOAD_DIR`/`uploads/`) — 연/월 샤딩(`YYYY/MM/`)된 원본·표시본·썸네일 파일
- 백업은 이 데이터 폴더 복사가 전부. 운영 배포는 Docker(`/data` 볼륨) 또는 맥 launchd([start.sh](../../scripts/mac-server/start.sh), 외장SSD 마운트 확인 후 `next start`).

## 인증 경계

- 첫 가입자가 자동 관리자, 이후는 초대코드 필수.
- 미들웨어가 `/login`·`/signup`과 일부 API(`api/auth`, `api/ingest`)를 제외한 모든 경로에 로그인을 강제. API/미디어는 미인증 시 401, 페이지는 `/login` 리다이렉트.
- `/api/ingest`는 세션 대신 Bearer 토큰(IngestToken)으로 인증 → 미들웨어 제외.
