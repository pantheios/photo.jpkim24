# 사진 동기화 개요

> **소스:** [scripts/mac-sync/sync.py](../../scripts/mac-sync/sync.py), [scripts/mac-sync/README.md](../../scripts/mac-sync/README.md), [src/app/api/ingest/route.ts](../../src/app/api/ingest/route.ts), [src/lib/sync.ts](../../src/lib/sync.ts)

사진이 들어오는 경로는 셋이며 모두 공통 미디어 파이프라인으로 수렴한다.

## ① 맥 사진 동기화 (권장, 현재 주력)

맥 "사진" 앱이 **단일 원천**. `launchd`가 1시간마다 [sync.py](../../scripts/mac-sync/sync.py)를 실행한다.

1. **추출** — `osxphotos export`로 설정의 `persons`(예: 아이 이름들)로 인식된 사진만 추출. 파일명=UUID, 보정본 우선, RAW 제외, iCloud 최적화 원본은 자동 다운로드(`--download-missing`), `--touch-file`로 파일시각=촬영시각.
2. **메타 로드** — export 결과 DB(`.osxphotos_export.db`)에서 사진별 **인물·EXIF·위치**를 읽음.
3. **업로드** — 파일마다 `/api/ingest`에 Bearer 토큰 + multipart 전송: `uuid`, `isVideo`, `takenAt`, `persons`, `meta`. 300MB 초과는 전송 없이 건너뜀.
4. **서버 처리** — [/api/ingest](../../src/app/api/ingest/route.ts)가 표시본·썸네일 생성, 촬영일별 Post에 묶음, 인물↔아이 이름 매칭 시 MediaChild 태깅, meta 저장.

특징: 공개 링크 불필요(외부 노출 없음), 원본 화질. 맥이 켜져 있을 때만 동작.

## ② iCloud 공유앨범 (대안, 현재 비활성)

공유앨범 "공개 웹사이트" 링크의 토큰만으로 비공식 webstream API를 호출([icloud.ts](../../src/lib/icloud.ts))해 사진을 받아온다. 서버의 주기 타이머([instrumentation-node.ts](../../src/instrumentation-node.ts), 기본 30분)가 [syncICloud](../../src/lib/sync.ts)를 호출. 맥 없이 서버 단독 동작하지만 비공식 API 의존·링크 노출 위험. 운영 환경에선 `ICLOUD_SYNC_DISABLED=1`로 꺼져 있음.

## ③ 직접 웹 업로드

로그인한 가족이 `/upload`에서 다중 업로드 → [/api/upload](../../src/app/api/upload/route.ts). 한 번의 업로드가 한 Post. 50MB 제한, 이미지 EXIF 중 가장 이른 날짜를 게시물 촬영일로.

## 중복 방지 (2중)

- **클라이언트(맥)**: 업로드 완료 UUID를 `~/.photo-album-sync-state.txt`에 기록 → 다음 실행에서 export 자체를 건너뜀.
- **서버**: `Media.externalId`(UUID/photoGuid) 유니크 제약 → state 파일이 사라져도 중복 임포트 안 됨. ingest는 중복이면 `{duplicate:true}`로 즉시 성공 처리.

## 한계 (한 방향 동기화)

- 이미 올라온 사진은 갱신 안 됨 — 사진 앱에서 얼굴/날짜를 고쳐도 기존 사진엔 반영되지 않음. 교정은 웹에서 직접([api/media/[id]/children](../../src/app/api/media/[id]/children/route.ts)).
- 동영상은 얼굴 인식이 없어 자동 아이 태깅 불가 → 웹에서 수동 태깅.

자세한 사유는 [동기화 방식 osxphotos vs iCloud](../decisions/002_사진동기화_osxphotos_vs_icloud.md).
