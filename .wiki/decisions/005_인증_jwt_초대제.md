# 결정 005 — 인증: JWT 세션 + 초대제 + Bearer 인입 토큰

> **소스:** [src/lib/session.ts](../../src/lib/session.ts), [src/middleware.ts](../../src/middleware.ts), [src/app/api/auth/signup/route.ts](../../src/app/api/auth/signup/route.ts)

## 결정
- 사용자 세션은 **JWT(jose, HS256)를 httpOnly 쿠키**에 담아 30일 유지.
- 가입은 **초대제** — 첫 가입자가 자동 관리자, 이후는 관리자 발급 초대코드 필수.
- 맥 동기화 에이전트는 세션이 아니라 **Bearer IngestToken**으로 인증(미들웨어 제외).

## 맥락
가족만 들어오는 비공개 공간이어야 하고, 자체 회원가입을 열어두면 안 된다. 동시에 헤드리스 에이전트(맥)도 서버에 업로드할 수 있어야 한다.

## 사유
- **JWT 쿠키 + Edge 미들웨어**: 세션 검증을 prisma 없이 순수 토큰 함수([session.ts](../../src/lib/session.ts))로 분리 → 미들웨어(Edge)에서 모든 경로를 저렴하게 보호. API/미디어는 401, 페이지는 `/login` 리다이렉트.
- **초대제**: 공개 가입을 막는 가장 단순한 모델. 첫 사용자=관리자 부트스트랩으로 별도 설정 불필요. 초대코드는 헷갈리는 글자 제외.
- **Bearer 인입 토큰**: 에이전트는 쿠키 세션을 쓰기 어렵다. `/api/ingest`만 미들웨어에서 제외하고 토큰으로 별도 인증, 토큰 값은 발급 시 1회만 노출·관리자가 폐기 가능.

## 트레이드오프
- JWT는 서버측 무효화가 없음(만료까지 유효) — 가족 규모에선 수용. `SESSION_SECRET` 유출 시 전체 토큰 위험.
- 인입 토큰이 평문으로 보관됨(가족 셀프호스팅 신뢰 경계 내라 수용).
